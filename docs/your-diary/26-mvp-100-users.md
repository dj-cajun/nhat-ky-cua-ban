# 26 — 100명 MVP 재기획

> **상태**: 기획 고정 (구현 대기)  
> **최종 갱신**: 2026-07-27  
> **목표**: 실사용자 **약 100명**이 같은 학교 경계 안에서 서클을 만들고, 서로의 하루를 방문하는 **클로즈드 앱**  
> **디자인 잠금**: 다이어리 = **현재 파스텔 연필 미니홈피** (`DiaryHompyHome`) — 교체·장면 스트립 재도입·다른 셸로 갈아끼우기 **금지**

---

## 1. 제품 한 줄

> 같은 학교라는 문 안에서, 세 사람이 연 작은 서클로 들어가,  
> **파스텔 미니홈피**에 오늘을 남기고 조용히 방문한다.

```text
학교 = 입장 경계
서클 = 관계 단위
다이어리(현재 홈피 UI) = 제품 중심
```

---

## 2. 잠금 / 금지

### 잠금 (바꾸지 않음)

| 항목 | 고정값 |
|------|--------|
| 다이어리 UI | 파스텔 OutlineBox · 점지 · 프로필 · 주간 · 미니앨범 · 써클/방명록/자유 게시판 · 음악 슬롯 |
| 코어 플로우 | 인트로 → 우주 → 서클 방 → 원 탭 → 미니홈피 |
| 관계 모델 | 학교 인증 ≠ 서클 가입 · 3인 개척 · 추천 가입 |
| 방문 원칙 | 조회수·방문 알림 없음 |

### 100명 전까지 만들지 않음

- 학교 전체 피드 / 전교 검색 / 학교 익명판  
- 채팅·DM 타임라인 확장 (쪽지 최소 유지)  
- 꾸미기 상점·방문자 카운터·보상·랭킹  
- 공개 소셜·탐색·알고리즘 추천  
- 앱 내 Spotify 풀 플레이어  
- 다이어리 셸을 어두운 장면/카드형으로 재설계  
- 새 메이저 공간(포커스룸 고도화 등) — **100명 이후**

---

## 3. 100명 MVP가 통과해야 하는 사용자 여정

한 유저가 아래를 **데모 없이** 끝낼 수 있어야 한다.

```text
1. 실로그인 (Apple 우선 · 가능하면 Google/email)
2. 학교 코드로 인증 요청 → verified (또는 ops 승인)
3. 인트로 1회 → 우주
4. 서클 개척 (나 + 친구 2 수락) 또는 초대 가입
5. 서클 방 → 원 탭 → 친구/내 미니홈피
6. 오늘 일기 쓰기 (기분 · 짧은글 · 필요 시 사진)
7. 방명록/자유게시판 최소 1회
8. 차단 또는 신고가 동작함을 운영이 확인
```

성공 정의 (100명 시점):

| 지표 | 목표 |
|------|------|
| 활성 계정 | ≈ 100 (같은 학교 1~2곳) |
| open 서클 | ≈ 15~25 |
| 주간 일기 작성 유저 | 서클 멤버의 절반 이상 |
| 치명 보안 이슈 | 0 (비서클 열람·가명 ID 유출·세션 누수) |
| 일기 UI 이탈 | “홈피가 바뀌었다” 피드백 0을 목표로 **디자인 잠금 유지** |

## 4. 현재 위치 → 100명 트랙

```text
지금 (데모 MVP)
  인트로·우주·서클·파스텔 홈피 플로우 시연 가능
  로컬/데모 의존 · staging JWT·실로그인 미통과 · E5 실데이터 일부 미연결

↓ Track P — 출시 가능 뼈대
↓ Track Q — 100명 운영 가능
↓ Track R — 초대·관찰 (기능 확장 금지)
```

기존 Phase 표와의 매핑:

| 새 트랙 | 기존 | 하는 일 |
|---------|------|---------|
| **P0** | 디자인 잠금 | 다이어리 = 현 홈피 고정 · 문서/리뷰 게이트 |
| **P1** | E5 축소판 | 홈피·서클·우주에 **실데이터만** 연결 (UI 변경 최소) |
| **P2** | 11.5 + H | 실로그인 · staging · 실기기 게이트 |
| **Q1** | C/D 운영 | 학교 코드 초대 · ops 승인·신고 처리 루틴 |
| **Q2** | 안정화 | 크래시·권한·오프라인·세션 전환 하드닝 |
| **R** | 베타 | 100명 초대 · 버그·치명 UX만 패치 |

---

## 5. Track P — 출시 가능 뼈대

### P0. 디자인 잠금 (즉시)

- 제품 경로 `/diary/[userId]` = `DiaryHompyHome` only  
- E2 프로토타입도 같은 셸  
- PR/리뷰 질문: “홈피 레이아웃을 바꿨는가?” → Yes면 반려  
- 장면 스트립·다른 다이어리 셸 재도입 금지 (100명 이후 재논의)

### P1. 실데이터 연결 (UI 유지 · E5 축소)

홈피/서클이 **시연용 fixture가 아니라** 계정 데이터를 읽게 한다.  
UI 블록은 그대로 두고 데이터만 붙인다.

| 우선 | 연결 대상 | 비고 |
|------|-----------|------|
| 필수 | 오늘 일기 CRUD · 주간 스트립 | 홈피 심장 |
| 필수 | 써클게시판 미리보기 · 방명록 · 자유게시판 | 이미 섹션 있음 |
| 필수 | 서클 방 멤버 오브 → 실프로필 | 원 탭 → 홈피 |
| 필수 | 우주 서클 칩 · close-3 (로컬 수동 유지 OK) | 자동 친밀도 금지 |
| 있으면 좋음 | 공지 1개 · 쪽지 진입 · Spotify 카드 | 새 UI 금지, 슬롯만 |
| 나중 | 토마토/포커스룸 · 달력 고도화 | 100명 이후 |

### P2. 실계정 · 실기기

| 게이트 | 내용 |
|--------|------|
| 로그인 | Apple 실동작 (US) · 세션 복구 |
| staging | JWT·RLS·학교 RPC 실측 (구 B.1/H) |
| 기기 | iOS 실기기에서 인트로→홈피 풀패스 1회 |
| 보안 | [15](./15-beta-launch-checklist.md) A열 하드 게이트 |

데모 단축으로 게이트를 “통과” 처리하지 않는다.

---

## 6. Track Q — 100명 운영

### Q1. 학교 한정 초대

- 베타 학교 1곳(또는 2곳) 코드만 발급  
- verified 전에 서클 개척 불가 (이미 가드 유지)  
- ops: 인증 큐 · 신고 · 멤버십 정지 최소 루틴  
- 초대 메시지 템플릿: “학교 코드 → 서클 3인 → 홈피에 오늘 쓰기”

### Q2. 안정화 범위 (기능 추가 아님)

- 크래시 / 빈 서클 / 권한 deny 카피  
- 세션 전환 시 이전 계정 데이터 비침  
- 오프라인 일기 초안 유지  
- 인트로 1회 정책 유지 (강제 루프 금지)

---

## 7. Track R — 100명 관찰

초대 시작 후 **새 모듈 금지**. 허용은:

- 출시 블로커 버그  
- 권한·보안 구멍  
- 홈피에서 글을 못 쓰는 치명 UX  

관찰 질문 (주 1회):

1. 서클을 만들었는가?  
2. 친구 홈피에 들어갔는가?  
3. 오늘을 썼는가?  
4. “디자인이 바뀌어 헷갈렸다”가 나왔는가? → 나오면 **되돌림**, 새 디자인 실험 금지

## 9. 완료 판정 체크리스트

100명 MVP **GO** 조건 (모두 충족):

- [ ] 다이어리 UI = 현 파스텔 홈피 (잠금 유지)  
- [ ] 실로그인으로 인트로→우주→서클→홈피→오늘 쓰기 가능  
- [ ] 학교 코드 초대 → verified → 서클만 활동  
- [ ] 비서클·차단·가명 ID 하드 게이트 통과  
- [ ] ops가 신고·인증을 실제 처리  
- [ ] 초대 인원 ≈ 100, open 서클 ≥ 15  

**NO-GO** 예:

- 홈피를 다른 셸로 교체하려 함  
- staging 없이 데모만으로 초대  
- 학교 피드/채팅 등 범위 밖 기능 착수

## 10. 다음 구현 순서 (에이전트/팀)

```text
P0 문서·잠금 반영          ← 본 문서
P1 홈피/서클/우주 실데이터 (UI 변경 없이)
P2 실로그인 + staging 실측
Q1 학교 코드 초대 운영
Q2 하드닝
R  초대 · 관찰만
```

사용자 지시어:

- `다음` → P1부터 코드  
- `디자인 바꿔` → **거절** (100명 잠금)  
- `100명 이후` → 포커스룸·연출 재논의 가능
