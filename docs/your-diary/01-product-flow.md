> **상태**: 현행 (US 제품 기준) · 학교 신뢰 경계 기획 반영  
> **최종 갱신**: 2026-07-25  
> **출처**: 기능 플로우 구현 계획서 + 시장 피벗 + [20-school-trust-boundary-plan.md](./20-school-trust-boundary-plan.md)

## 핵심 원칙

세 사람이 신뢰의 문을 연다. 초대 링크만으로는 들어올 수 없다.  
서클 안에서만 서로의 하루를 조용히 방문한다.

**학교**는 입장 가능한 관계의 **바깥 경계**다. 학교 전체 피드·전교 검색·학교 익명판은 만들지 않는다.  
**서클**이 실제 활동 단위이고, **다이어리**가 제품의 중심이다.

문서에서 「미니홈피」는 **카테고리명이 아니라** 한 사람의 페이지를 찾아가 하루를 보는 **구조 비유**다.  
학교 커뮤니티·방문자 카운터·선물 경제 제품이 아니다.

| 원칙 | 의미 |
|------|------|
| 학교 경계 | verified 같은 학교만 초대·추천 후보 — 전교 로스터 없음 ([20](./20-school-trust-boundary-plan.md)) |
| 폐쇄성 | 개척 3인 / 가입 추천 3인 — 서버가 단일 소스 (학교 소속만으로 입장 불가) |
| 조용한 방문 | 조회수·방문 알림 없음 |
| 클라이언트 불신 | 개척·가입·한도·신고·학교 멤버십은 RPC / Edge / RLS |
| 가명 전 안전 | 신고·차단·모더레이션이 가명 게시판보다 앞 |

## 사용자 여정 (요약)

```text
가입 (Apple → Google → email / demo)
→ 학교 인증 (베타: 학교 코드 + 추천/운영 승인)   ← 기획 [20], 구현 Phase C
→ 내 우주 (서클 지도)
→ 서클 개척 (같은 학교 · 본인 + 친구 2명 수락 → open)
→ 멤버 카드 → 친구 다이어리 (기분 / 10자 / 짧은글 / 사진 / 음악)
→ 공지·투표 (서클당 활성 1개)
→ Presence (초록=접속, 주홍=응답 후) · 일시 기척 배너(비저장)
→ (가입) 초대 → 멤버 3명 추천 → 서버 승인
→ 신고·차단
→ 가명 게시판·쪽지 (서클 안 · 안전 장치 이후)
→ Spotify 카드
```

---

## 서클 개척 (1~3단계 범위)

1. 한 사람이 임시 이름 + 친구 2명 지목  
2. 두 초대가 모두 수락해야 정식 서클 생성  
3. `open_circle_from_draft` — 정확히 3명 수락 시에만 트랜잭션으로 open  
4. 거절 시 초안 취소, 서클 행 없음  

---

## 다이어리 방문 (「미니홈피」는 구조 비유)

- **UI 잠금 (100명까지)**: 파스텔 연필 미니홈피 `DiaryHompyHome` — [26](./26-mvp-100-users.md)
- 기분, 10자 노트, 짧은 본문, 대표 사진, 음악 카드  
- 공개 범위: `private` / `selected_circles` / `all_circles`  
- `entry_date` + `timezone` (기본 `America/New_York`)  
- 차단 관계면 상호 일기 열람 불가  
- 꾸미기 상점·TODAY/TOTAL 방문자 없음 (아카이브 제품과 구분)
- 어두운 장면 전면 셸·카드형 홈피로 **교체하지 않음**

---


## 공지 · 투표

- 서클당 **활성 1개**  
- 투표 결과는 **합계만** (`get_poll_summary`) — 개인 선택 비공개  
- 응답은 DB 저장 성공 후에만 주홍 Presence  

---

## Presence

- 초록: 서클에 지금 있음  
- 주홍: 활성 공지/투표에 응답함  
- last_seen을 초 단위로 DB에 쓰지 않음 (Realtime Presence 목표)  

---

## 가입 (4단계) — 상세는 [04-phase-4-join.md](./04-phase-4-join.md)

초대 링크만으로 멤버가 될 수 없다.  
아는 멤버 3명 추천 → 서버 집계 → 3이면 자동 가입.  
신청자에게 추천자 신원·결정은 비공개.

---

## 신고 · 차단

- 콘텐츠 스냅샷 보관 (수정·삭제 후에도 심사 가능)  
- 차단은 양방향 열람/쪽지 차단  
- **가명 기능 전에** 경로가 있어야 App Review에 안전  

---

## 가명 게시판 · 쪽지

- 실작성자 ID는 클라이언트에 노출하지 않음  
- 신고·차단·모더레이션 이후에만 본격 오픈
